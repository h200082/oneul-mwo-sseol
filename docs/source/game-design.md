# 뭐 먹을 거냥? — 최종 게임 기획서

> 문서 버전: 1.1<br>
> 작성일: 2026-07-27<br>
> 상태: 해커톤 MVP 제작 기준선<br>
> 게임 제목: **뭐 먹을 거냥?**

## 1. 프로젝트 개요

### 한 줄 소개

최대 8명이 마음에 드는 메뉴는 포획하고 나머지는 정확히 반으로 가르며, 식사 내기 순위와 서로의 메뉴 취향을 함께 발견하는 60초 브라우저 파티게임.

### 핵심 목적

이 게임은 최종 메뉴를 강제로 결정하지 않는다.

- 게임은 플레이 실력으로 1등부터 꼴찌까지의 순위를 정한다.
- 포획 결과로 각 참가자가 먹고 싶어 한 메뉴를 보여준다.
- 가장 많이 겹친 메뉴를 보여줘 참가자들의 합의를 돕는다.
- 실제로 먹을 메뉴는 결과 화면을 본 참가자들이 함께 결정한다.

| 구분 | 게임이 제공하는 결과 |
|---|---|
| 실력 경쟁 | 전체 순위, 1등, 꼴찌, 평균 정확도 |
| 취향 정보 | 참가자별 포획 메뉴 0~2개 |
| 합의 보조 | 가장 많이 겹친 메뉴와 포획 인원 |
| 사람의 결정 | 실제로 먹을 최종 메뉴 |

### 핵심 재미

1. **즉시 이해되는 두 행동**<br>
   먹고 싶은 메뉴는 약 0.3초 길게 눌러 포획하고, 나머지는 스와이프로 반으로 가른다.
2. **짧고 명확한 실력 경쟁**<br>
   한 판 약 45~60초 안에 면적 분할 정확도로 순위를 정한다.
3. **취향 발견**<br>
   플레이가 끝난 뒤 친구들과 어떤 메뉴가 겹쳤는지 확인한다.
4. **실제 행동으로 이어지는 결과**<br>
   결과를 보며 메뉴를 합의하고 꼴찌가 1등의 식사를 부담하는 내기를 실행한다.

## 2. 대상 사용자와 플레이 상황

### 주요 대상

- 점심·저녁 메뉴를 정하지 못한 친구, 동료, 연인
- 직접 만나 식사 메뉴와 내기 결과를 가볍게 정하고 싶은 2~8인 모임
- 혼자 짧은 아케이드 게임을 즐기며 먹고 싶은 메뉴 후보를 찾고 싶은 사용자

### 사용 상황

- 회사 또는 학교에서 점심을 고르기 직전
- 친구들과 저녁 식사를 정할 때
- 친구들과 가볍게 식사 내기를 할 때

### 플랫폼

- 모바일 브라우저 세로 화면 우선
- 데스크톱 브라우저의 마우스 드래그 지원
- 설치 없이 GitHub Pages 링크로 즉시 실행

## 3. 게임 모드

### 혼자 하기

- 메뉴 50개 풀에서 20개가 출제된다.
- 최대 2개까지 마음에 드는 메뉴를 포획할 수 있다.
- 결과에서 평균 정확도, 포획 메뉴, 개인 최고 기록을 확인한다.
- 메뉴를 포획하지 않았어도 정상적으로 결과를 제공한다.

### 방 만들기

- 2~8인이 각자의 기기에서 같은 판을 플레이한다.
- 방장은 QR 코드, 초대 링크, 방 코드를 통해 참가자를 초대한다.
- 모든 참가자는 같은 메뉴, 이미지, 순서, 위치, 속도 조건으로 플레이한다.
- 최종 결과에서 전체 순위와 모든 참가자의 포획 메뉴를 함께 확인한다.

## 4. 방 설정

방 생성 시 설정은 식사 시간 한 가지로 제한한다.

### 식사 시간

- 점심
- 저녁

점심과 저녁은 별도 메뉴 풀을 사용하지 않는다. 하나의 한국 일상 메뉴 풀에 `점심 가중치`와 `저녁 가중치`를 두어 등장 확률만 조정한다.

### 고정 내기 규칙

방 대전에는 별도의 내기 선택을 제공하지 않는다.

- 꼴찌가 1등의 식사 1인분을 부담한다.
- 실제 메뉴, 가격, 구매 범위는 참가자들이 합의한다.
- 공동 1등 또는 공동 꼴찌가 나오면 부담 방식은 참가자들이 합의한다.
- 혼자 하기에는 내기 규칙을 적용하지 않는다.

### 설정에서 제외하는 항목

- 추가 내기 설정
- 가격대
- 매운맛 단계
- 제외 음식
- 포획 횟수 선택
- 준비 여부
- 방 최대 인원 선택

가벼운 게임의 시작 피로도를 줄이기 위해 포획 가능 횟수는 최대 2회, 방 최대 인원은 8명으로 고정한다.

## 5. 전체 플레이 흐름

### 혼자 하기

1. 홈에서 `혼자 하기` 선택
2. 점심 또는 저녁 선택
3. 자동 연습 없이 메뉴 20개를 바로 플레이
4. 평균 정확도와 포획 메뉴 확인
5. 같은 메뉴로 한 판 더, 새 메뉴 고르기 또는 홈으로 이동

### 방 플레이

1. 방장이 `방 만들기` 선택
2. 점심 또는 저녁 선택
3. 방 생성 후 QR, 초대 링크, 방 코드 표시
4. 참가자가 QR 또는 코드로 입장하고 닉네임 설정
5. 대기실에 2명 이상 입장하면 방장의 `N명으로 시작` 버튼 활성화
6. 방장이 시작하면 `waiting`에서 `preparing`으로 전환하고 참가 명단과 설정을 잠금
7. 잠긴 참가자들이 필요한 20개 메뉴 에셋을 제한 시간 안에 자동 로딩하고 기기별 준비 완료를 전송
8. 전원 준비가 확인되면 `started`와 공통 `startAt`을 확정하고 4초 카운트다운
9. 자동 연습 없이 모든 참가자가 같은 20개 메뉴 판을 각 기기에서 독립 실행
10. 결과 제출 후 전체 순위와 취향 정보 표시

사용자가 누르는 별도의 `준비` 버튼은 제공하지 않는다. `preparing`의 준비 완료는 각 기기가 프리로드를 마치거나 제한 시간 폴백을 확정한 뒤 자동으로 전송한다.

## 6. QR 및 방 참가

### 참가 방법

1. 휴대폰 기본 카메라로 QR 스캔
2. 게임 홈의 `QR로 참가`에서 앱 내 카메라 사용
3. 8자리 방 코드 직접 입력
4. 초대 링크 공유

### QR 형식

QR에는 GitHub Pages의 전체 HTTPS 주소와 방 식별자를 넣는다.

```text
https://사용자.github.io/저장소/?room=ROOM_ID
```

GitHub Pages 새로고침 시 하위 경로 404를 피하기 위해 `/room/ROOM_ID`보다 쿼리 파라미터를 사용한다.

### 방 규칙

- 최소 시작 인원: 2명
- 최대 인원: 8명
- 시작 후 추가 입장 불가
- 방장이 시작하면 참가 명단 잠금
- 자동 로딩 제한 시간: 30초
- 로딩 실패자가 있으면 방장에게 제외 후 시작 또는 취소 선택 제공
- 방장 이탈 시 가장 먼저 입장한 접속자에게 방장 권한 이전
- 방은 생성 후 일정 시간이 지나면 만료

## 7. 핵심 플레이 규칙

### 라운드 구성

- 전체 메뉴 풀: 한국 일상 메뉴 최소 50개
- 한 판 출제 수: 중복 없는 20개
- 한 번에 등장하는 메뉴: 1개
- 등장 방향: 화면 위에서 아래로 낙하
- 처리 가능 구간: 등장 지점부터 하단 기준선 도달 전까지
- 기준선을 넘긴 비포획 메뉴: 놓침 0점
- 한 판 목표 시간: 약 45~60초

### 메뉴 토큰

음식 이미지는 원형으로 잘라 넣지 않는다. 투명 배경의 실제 실루엣과 원본 가로세로 비율을 유지해 가로형·세로형·불규칙형 음식이 서로 다르게 보이게 하며, 베기 성공과 점수도 보이는 음식 형태를 따른다.

- 이미지가 있는 메뉴는 WebP의 실제 불투명 알파 실루엣을 판정 마스크로 사용한다.
- 실제 음식 이미지는 최대 표시 영역 안에 `contain` 방식으로 배치해 찌그러뜨리지 않는다.
- 선이 실제 음식 픽셀을 통과하고 실루엣 양쪽 끝을 덮어야 베기로 인정한다. 투명한 모서리·구멍·분리된 조각 사이의 공기는 베기로 인정하지 않는다.
- 절단 정확도는 선 양쪽에 남은 알파 가중 면적 중 작은 쪽의 비율을 기준으로 0~100점으로 계산한다.
- 1% 미만의 아주 작은 조각과 2px 미만 접촉은 접선 노이즈로 거부한다.
- 이미지가 없거나 브라우저가 알파 마스크를 읽지 못한 메뉴만 기존 반지름 64px 원형 판정으로 안전하게 대체한다.
- 포획은 음식마다 지나치게 어려워지지 않도록 실제 실루엣보다 넓은 공통 길게 누르기 범위를 유지한다.
- 같은 메뉴의 변형 이미지를 추가할 때는 참가자 모두가 같은 변형을 선택하도록 방 시드·라운드 번호를 사용하고, 선택된 이미지마다 자신의 알파 마스크를 사용한다.

### 행동 1: 베기

- 화면을 터치 또는 클릭한 채 메뉴 토큰의 안쪽을 스치도록 드래그한다.
- 드래그 중에도 메뉴 토큰은 멈추지 않고 계속 낙하한다.
- 테두리에서 시작해 반대 테두리까지 정확히 통과할 필요는 없다. 충분히 길고 곧은 경로가 음식 양쪽을 거의 덮으면, 각 끝점에서 테두리까지 최대 32px만 보정해 시작점이나 끝점이 안쪽이어도 베기로 인정한다.
- 이동 중인 토큰과 실제로 접촉했는지는 토큰 기준 상대 경로로 확인하고, 절단 방향은 화면에 그린 드래그 방향을 따른다.
- 사용자가 그은 선을 기준으로 토큰이 두 조각으로 분리된다.
- 두 조각은 반대 방향으로 회전하며 떨어진다.
- 절단 직후 정확도 수치와 평가 문구를 표시한다.

### 행동 2: 포획

- 먹고 싶은 메뉴 토큰을 약 0.32초 동안 움직이지 않고 길게 누른다.
- 누르기 시작한 토큰을 포획 대상으로 잠그며, 포획 대기 중에도 토큰은 계속 낙하한다.
- 최초 접촉점에서 14px을 넘겨 움직이면 포획 대기를 취소하고 같은 입력을 즉시 베기로 전환한다.
- 최대 2개까지 포획할 수 있다.
- 포획권을 반드시 사용할 필요는 없다.
- 짧게 눌렀다 떼거나 입력이 취소되면 라운드와 포획 슬롯을 소모하지 않는다.
- 자동 포획과 미사용 포획권 페널티는 없다.
- 포획 실패 시 포획 슬롯을 소모하지 않는다.

포획 성공 조건:

1. 포인터가 메뉴 토큰의 포획 영역 안에서 시작함
2. 같은 포인터를 약 0.32초 동안 유지함
3. 최초 접촉점에서 이동 거리가 14px 이하임
4. 대상 토큰이 아직 활성 상태이며 남은 포획 슬롯이 있음

포획 성공 시:

1. 진행 링과 에너지 끈이 완성되며 포획 버스트 생성
2. 토큰이 한 바퀴 회전
3. 토큰이 화면 상단 또는 측면의 포획 슬롯으로 이동
4. `포획 1/2` 상태 갱신

### 제스처 우선순위

1. 포획 영역 안에서 누르면 길게 누르기 대기 상태로 진입
2. 대기 중 14px을 넘겨 움직이면 즉시 베기 상태로 전환
3. 움직이지 않고 약 0.32초를 채우면 포획
4. 포획 영역 밖에서 시작했거나 포획 슬롯이 없으면 드래그를 베기로 판정
5. 짧은 탭이나 유효하지 않은 경로는 행동 실패로 처리하되 라운드는 소비하지 않음

## 8. 점수 규칙

### 개별 절단 정확도

절단선이 토큰을 나눈 두 면적을 `A`, `B`라고 한다.

```text
정확도 = 100 × (1 - |A - B| ÷ (A + B))
```

예시:

| 분할 비율 | 정확도 |
|---|---:|
| 50:50 | 100점 |
| 60:40 | 80점 |
| 75:25 | 50점 |
| 토큰을 제대로 통과하지 못함 | 0점 |
| 기준선 아래로 놓침 | 0점 |

### 최종 점수

포획한 메뉴는 취향 표현이므로 점수 계산에서 제외한다.

```text
최종 평균 = 비포획 메뉴의 점수 합 ÷ 비포획 메뉴 수
```

| 포획 수 | 점수 계산 대상 |
|---:|---:|
| 0개 | 20개 |
| 1개 | 19개 |
| 2개 | 18개 |

- 놓친 비포획 메뉴도 0점으로 분자와 분모에 포함한다.
- 결과 화면은 평균 정확도를 소수점 한 자리까지 표시한다.
- 순위 계산에는 반올림 전 원점수를 사용한다.
- `95점 이상`은 `칼각`으로 기록한다.

### 점수 설계 의도

포획 수에 따라 분모가 18~20으로 달라지는 것은 의도된 규칙이다. 엄격한 경쟁 공정보다 마음에 드는 음식만 포획한다는 취향의 진정성을 우선한다.

전략적으로 어려운 음식만 포획하는 문제는 모든 메뉴 토큰의 크기와 면적 판정 난도를 통일하여 줄인다.

### 동점 처리

표시·제출 점수인 소수 둘째 자리 평균이 같으면 공동 순위로 처리한다. 예를 들어 `100, 90, 90, 80`은 `1위, 공동 2위, 공동 2위, 4위`가 된다. 방 입장 순서와 플레이어 ID는 같은 점수 안의 표시 순서만 안정화하며 승패를 가르지 않는다.

공동 1등 또는 공동 꼴찌일 때 식사 부담 방식은 참가자들이 합의한다. 해커톤 MVP에서는 별도의 강제 서든데스를 제공하지 않는다.

## 9. 난이도

음식 인식, 선호 판단, 제스처 선택이 모두 필요하므로 한 번에 메뉴 하나만 등장시킨다.

권장 초기 속도:

| 구간 | 기준선까지의 낙하 시간 |
|---|---:|
| 1~5번째 | 약 2.6초 |
| 6~15번째 | 약 2.2초 |
| 16~20번째 | 약 1.8초 |

난이도는 다음 요소로 조절한다.

- 낙하 속도
- 가벼운 좌우 이동
- 토큰 회전
- 등장 위치 변화

토큰 크기를 과도하게 줄이거나 이미지를 알아보기 어렵게 만드는 방식은 사용하지 않는다.

## 10. 결과 화면

게임은 최종 메뉴를 자동 선택하거나 강제하지 않는다.

### 영역 1: 전체 순위

1등부터 최대 8등까지 나열한다.

각 순위 행의 정보:

- 순위
- 닉네임
- 평균 정확도
- 포획한 음식 이미지 최대 2개
- 이미지 아래의 작은 음식 이름

예시:

```text
1위 지수   평균 정확도 92.4%
[라면 이미지] [초밥 이미지]
    라면          초밥
```

포획하지 않은 슬롯도 삭제하지 않고 빈 카드로 표시한다.

```text
[치킨 이미지] [빈 슬롯]
    치킨        포획 없음
```

### 영역 2: 경기 결과 요약

다음 정보를 이미지 중심으로 다시 보여준다.

1. 1등의 이름과 평균 정확도
2. 1등이 포획한 메뉴 0~2개
3. 가장 많이 겹친 메뉴 또는 카테고리 근접 취향
4. 공동 최다 메뉴·카테고리가 있으면 모두 표시
5. 꼴찌의 이름과 평균 정확도
6. 고정 내기 결과: 꼴찌가 1등의 식사를 부담한다는 안내

예시:

```text
경기 결과 요약

1등: 지수 · 92.4%
1등의 포획 메뉴: [라면] [초밥]

우리 취향 1위
[김치찌개 이미지] ×4명
지수 · 민수 · 하나 · 준호

꼴찌: 준호 · 61.2%
내기 결과: 준호가 지수의 식사를 부담해요!
```

### 겹친 메뉴 집계

- 동일한 `menuId`를 포획한 서로 다른 플레이어 수를 센다.
- 2명 이상 포획한 메뉴만 `겹친 메뉴`로 인정한다.
- 가장 많은 사람이 포획한 메뉴를 `우리 취향 1위`로 표시한다.
- 최다 인원이 같은 메뉴가 여러 개면 모두 공동 1위로 표시한다.
- 아무도 포획하지 않았다면 정상적인 빈 결과 상태를 표시한다.

### 카테고리 근접 취향 폴백

- 정확히 겹친 `menuId`가 하나라도 있으면 기존 겹친 메뉴 결과를 우선한다.
- 정확히 겹친 메뉴가 없을 때만 기존 메뉴 카테고리로 가까운 취향을 계산한다.
- 같은 플레이어가 같은 카테고리 메뉴를 2개 포획해도 해당 카테고리에는 1명으로 센다.
- 서로 다른 완주자 2명 이상이 고른 카테고리 중 참여 인원이 가장 많은 카테고리를 표시한다.
- 최다 인원이 같은 카테고리가 여러 개면 카테고리 고정 순서로 모두 표시한다.
- 결과 문구는 `둘 다 면 요리파`, `오늘은 따뜻한 국물 취향`처럼 합의에 바로 쓸 수 있게 쓴다.
- 미완주자와 현재 카탈로그에 없는 과거 메뉴 ID는 집계에서 제외한다.
- 정확 일치와 카테고리 근접 일치가 모두 없으면 정상적인 빈 결과 상태를 표시한다.

### 결과 이후 행동

- 솔로: `같은 메뉴로 한 판 더`, `새 메뉴 고르기`, `홈으로`
- 방: 현재 방을 안전하게 나간 뒤 `새 메뉴 고르기` 또는 `홈으로`
- 같은 방 재대결은 시작 회차별 결과 저장과 참가자 재동의 상태 전이를 설계한 뒤 추가하는 후속 기능
- 결과 카드 공유

메뉴 확정 버튼, 제한 시간 선택, 자동 추첨은 제공하지 않는다.

## 11. 화면 구성

### 홈

주요 버튼:

- 혼자 하기
- 방 만들기
- QR로 참가
- 코드로 참가

보조 기능:

- 도구
- 업적
- 설정

해커톤 MVP에서 구현하지 않는 상점과 확장 모드는 홈에 노출하지 않는다.

### 방 만들기

```text
언제 먹나요?
[점심] [저녁]

꼴찌가 1등의 식사 1인분을 부담해요.

최대 8명 · 포획 최대 2개

[방 만들기]
```

### 대기실

- 큰 QR 코드
- 8자리 방 코드
- 링크 복사
- 공유하기
- 점심·저녁 설정과 고정 식사 내기 규칙 요약
- 최대 8명의 참가자 카드
- 방장 표시
- `N명으로 시작` 버튼

### 자동 로딩·카운트다운

- 방장이 시작하면 `waiting → preparing`으로 전환하고 참가 명단·덱·콘텐츠 버전 잠금
- 각 참가자의 제한 시간 자동 로딩과 기기별 준비 완료 상태 표시
- 전원 준비 완료 시 `preparing → started`로 전환하고 공통 `startAt` 기준 4초 카운트다운
- 사용자용 준비 버튼은 없음

### 플레이 화면

상단:

- 현재 평균 정확도 또는 누적 정보
- 진행도 `7/20`
- 포획 슬롯 `1/2`
- 효과음·BGM 마스터, 나레이션, 진동 토글

중앙:

- 낙하하는 음식 토큰
- 음식 이름
- 베기 궤적 및 포획 진행 링·에너지 끈

하단:

- 기준선
- 놓침 경고

### 결과 화면

- 상위 3명 시각 강조
- 1~8위 전체 순위
- 플레이어별 포획 메뉴 이미지
- 경기 결과 요약
- 최다 겹침 메뉴 이미지
- 재대결·공유·홈 버튼

8인의 정보를 담기 위해 세로 스크롤을 허용한다.

## 12. 시각 디자인

### 기본 방향

- 밝고 경쾌한 모바일 아케이드
- 음식은 고채도의 스티커 일러스트
- UI는 카드형이며 정보 계층이 명확해야 함
- 배경은 음식 토큰과 제스처 궤적보다 낮은 대비와 채도로 표현
- 특정 국가나 관광지 묘사 대신 식사 내기와 아케이드 플레이 상황을 강조

### MVP 배경: 팝 아케이드 다이닝 테이블

배경을 특정 장소의 풍경이 아니라 메뉴 대결이 벌어지는 플레이 테이블로 표현한다. 살짝 위에서 내려다본 식탁 중앙에 게임용 매트를 놓아 친구들과 식사 전에 한 판 벌이는 분위기를 만든다.

공간 구성:

- 화면 중앙 65~70%는 메뉴 토큰이 선명하게 보이는 비어 있는 플레이 매트
- 컵, 포크, 젓가락, 냅킨, 영수증, 소스통은 화면 가장자리에만 배치
- 배경 안에는 음식 그림, 메뉴명, 복잡한 무늬를 넣지 않아 플레이 오인 방지
- 음식 토큰에는 밝은 외곽선과 부드러운 그림자를 적용

색과 조명:

- 중앙 매트: 차콜·딥 네이비 계열 `#17212D`, `#243244`
- 주요 포인트: 크림 옐로 `#FFD76A`, 코럴 오렌지 `#FF795F`
- 포획 효과: 민트·시안 `#55E6D1`
- 점심은 크림·하늘색, 저녁은 네이비·코럴 조명 오버레이 사용
- MVP에서는 같은 기본 배경에 조명 오버레이만 바꿔 제작량을 줄임

움직임:

- 컵 표면의 작은 빛 반사와 냅킨 끝의 약한 흔들림만 4~6초 루프로 재생
- 연속 베기나 고득점 때 테이블 가장자리 조명이 짧게 반응
- 플레이 중 중앙 배경과 큰 소품은 움직이지 않음
- 큰 애니메이션은 시작과 결과 전환에서만 사용

레이어 순서:

1. 비네팅과 흐린 실내 조명
2. 테이블 표면과 중앙 플레이 매트
3. 가장자리 소품
4. 음식 토큰
5. 베기·포획 이펙트
6. 점수와 HUD

### 절단 연출

- 사용자가 그은 선을 따라 빛나는 궤적
- 도구마다 색·파티클·절단음 변화
- 절단 직후 두 조각 분리와 회전
- 정확도 수치가 팝업 아트로 등장
- 95점 이상이면 짧은 슬로모션과 `칼각!`

### 포획 연출

- 길게 누르는 동안 진행 링과 에너지 끈이 낙하하는 토큰을 따라감
- 성공 순간 링이 짧게 터지며 포획 상태를 명확히 표시
- 음식 토큰 한 바퀴 회전
- 포획 슬롯으로 빠르게 이동
- 결과 화면에서 동일 이미지를 재사용

## 13. 사운드

### 기본 구성

- 신나는 아케이드 BGM 1곡
- 기본 절단 효과음
- 포획 효과음
- 정확도 등급 효과음

- 효과음·BGM 마스터 음소거, 나레이션, 진동 개별 설정

저장된 설정이 없는 첫 실행에는 효과음·BGM 마스터, 지원 기기의 진동, 나레이션을 모두 켠다. 사용자가 명시적으로 끈 설정은 같은 브라우저에 저장해 다음 실행에도 유지한다. 마스터 사운드가 꺼져 있으면 나레이션의 개별 요청값을 바꾸지 않은 채 실제 음성 재생만 억제한다.

### AI 음성

유명 방송의 원본 음성이나 특정 인물의 말투·음색을 모사하지 않는다.

독자적인 변형 문구 예시:

- `현기증 오기 전에 포획!`
- `배고픔 경보!`
- `꼬들 타이밍 놓치지 마!`
- `라면 포획 완료!`

음성은 매번 재생하지 않고 특정 메뉴 포획 또는 낮은 확률의 특별 반응으로 사용한다.

사용한 TTS 도구, 모델, 프롬프트, 생성일, 이용 약관, 사람의 후편집 내용을 AI 활용 기술 문서에 기록한다.

## 21. 튜토리얼

튜토리얼은 첫 판에 자동 삽입하지 않고 홈의 `튜토리얼 하기`로만 진입한다. 일반 혼자하기와 방 플레이는 언제나 원래의 20개 라운드를 바로 시작하며, 별도 튜토리얼은 15~20초 이내로 구성한다.

1. 점수에 포함되지 않는 연습 토큰을 잘라 정확도 확인
2. 새 연습 토큰을 베지 않고 약 0.3초 길게 눌러 포획
3. 두 연습은 점수·실전 포획 슬롯·20개 덱 진행·개인 기록에 포함되지 않음
4. 포획은 선택이며 실전에서는 최대 2개라는 점 안내
5. 비포획 메뉴의 평균 정확도로 순위를 정한다는 점 안내
6. 결과에서 순위와 겹친 메뉴를 확인한다는 점 안내
7. 완료 화면에서 `다시 연습` 또는 `홈으로` 선택

튜토리얼 문구 예시:

```text
먹고 싶으면 음식 위를 0.3초 꾹 눌러 포획!
나머지는 음식 안쪽을 스치듯 드래그해 썰어보세요.
누른 채 움직이면 바로 베기로 전환됩니다.
마음에 드는 메뉴가 없다면 포획하지 않아도 됩니다.
```

## 22. 테스트 및 완료 기준

### 핵심 조작

- 처음 플레이한 사용자가 베기와 포획을 구분할 수 있음
- 드래그 중 음식이 멈추지 않고 낙하함
- 음식 안쪽에서 시작하거나 끝난 충분한 드래그도 베기로 판정됨
- 화면의 베기 방향과 실제 절단 방향이 일치함
- 길게 누르기 대기 중 14px을 넘겨 움직이면 포획 없이 베기로 전환됨
- 짧은 탭과 `touchcancel`이 라운드나 포획 슬롯을 소비하지 않음
- 50:50, 60:40, 75:25 점수가 정의와 일치함
- 포획 0개, 1개, 2개에서 평균 분모가 각각 20, 19, 18로 계산됨
- 놓친 비포획 메뉴가 0점으로 평균에 포함됨

### 멀티플레이

- QR, 링크, 코드로 같은 방에 참가 가능
- 8명이 동시에 입장해도 슬롯이 중복되지 않음
- 2명 이상이면 방장의 시작 버튼이 활성화됨
- 준비 버튼 없이 자동 로딩 후 카운트다운함
- 모든 참가자에게 동일한 20개 메뉴와 조건이 제공됨
- 시작 후 늦은 입장을 거부함
- 방장 이탈과 네트워크 재접속을 처리함

### 결과

- 1~8위 순위가 모든 기기에서 동일함
- 각 참가자의 포획 이미지가 정확히 표시됨
- 포획하지 않은 슬롯이 빈 카드로 표시됨
- 동일 `menuId`의 포획 인원을 정확히 집계함
- 공동 최다 겹침 메뉴를 모두 표시함
- 겹친 메뉴가 없거나 아무도 포획하지 않은 빈 상태를 처리함
- 꼴찌가 부담자, 1등이 수혜자로 정확히 표시됨
- 공동 1등 또는 공동 꼴찌이면 참가자 합의 안내가 표시됨
- 메뉴를 자동 확정하거나 강요하지 않음

### 기기

- Android Chrome
- iPhone Safari
- 데스크톱 Chrome 또는 Edge
- 세로형 모바일 화면
- 노치와 safe-area
- 페이지 스크롤·당겨서 새로고침으로 게임 입력이 끊기지 않음
- 첫 사용자 입력 후 오디오 정상 재생

## 24. 최종 확정 사항

- 게임은 최종 메뉴를 강제로 정하지 않는다.
- 최대 8인의 순위와 취향 합의를 돕는다.
- 포획은 최대 2회이며 사용하지 않아도 된다.
- 자동 포획과 포획 미사용 페널티는 없다.
- 비포획 메뉴의 평균 정확도로 순위를 정한다.
- 놓친 비포획 메뉴는 0점이다.
- 모든 참가자는 완전히 같은 20개 메뉴와 조건을 사용한다.
- 참가자용 준비 버튼은 없다.
- 2명 이상 입장하면 방장이 시작할 수 있다.
- 결과에는 1~8위, 개인 포획 메뉴 이미지, 1등의 포획 메뉴, 최다 겹침 메뉴, 꼴찌와 고정 식사 내기 결과를 표시한다.
- 방에서 추가 내기 설정을 선택하지 않으며 꼴찌가 1등의 식사를 부담한다.
- 최종 메뉴는 참가자들이 대화로 결정한다.
