# 최종 게임 기획서 작성

- 날짜: 2026-07-27
- 도구·모델: Codex (세부 모델명은 최종 문서 작성 시 실행 기록 기준으로 확정)
- 작업 목적: 사용자와 반복 검토한 음식 메뉴 선택·내기 아케이드 게임의 최종 제작 기준선 작성
- 관련 파일·기능: `docs/source/game-design.md`

## 주요 프롬프트·지시 사항

사용자는 다음 핵심 방향을 확정했다.

- 최대 8인 QR 방 플레이
- 방에서는 점심·저녁만 설정하고 꼴찌가 1등의 식사를 부담하는 규칙으로 고정
- 한국 일상 메뉴 50개 중 같은 20개 출제
- 원하는 메뉴만 최대 2개 포획하며 미사용 가능
- 포획 메뉴는 점수에서 제외
- 비포획 메뉴의 절단 정확도 평균으로 순위 결정
- 놓친 비포획 메뉴는 0점 처리
- 참가자용 준비 버튼 없이 방장이 2명 이상일 때 시작
- 결과에서 1~8위와 각자의 포획 메뉴 이미지를 표시
- 1등의 포획 메뉴, 가장 많이 겹친 메뉴, 꼴찌와 고정 식사 내기 결과를 요약
- 게임이 최종 메뉴를 강제 결정하지 않고 참가자 합의를 지원
- 유명 밈 원본 대신 독자적인 변형 대사와 일반 AI 음성 사용
- 배경은 관광지가 아닌 팝 아케이드 다이닝 테이블 콘셉트 사용

## 생성·제안 결과 요약

- 프로젝트 개요와 핵심 설계 원칙
- 솔로·최대 8인 방 플레이 흐름
- QR·링크·코드 참가와 자동 로딩 구조
- 베기·포획 제스처 규칙
- 면적 기반 점수와 비포획 평균 계산
- 순위·개인 포획·최다 겹침 중심의 결과 화면
- 메뉴 50개 콘텐츠 구조
- 시각·사운드·도구·업적 방향
- GitHub Pages와 Firebase 기반 기술 구조
- AI 활용 계획
- MVP, 확장 기능, 테스트 및 제출 기준

## 검토 및 수정

- 자동 포획 규칙을 제거했다.
- 포획 횟수는 0~2회로 허용했다.
- 결과에서 승자의 메뉴를 강제 선택하거나 무작위 추첨하는 규칙을 제거했다.
- 참가자의 수동 준비 버튼을 제거하고 방장 시작 이후 자동 로딩으로 대체했다.
- 8인 결과 화면에 음식 이미지를 표시하도록 설계했다.
- 점심과 저녁은 별도 풀 대신 동일 풀의 가중치로 구분했다.
- AI 음성은 특정 인물 모사 없이 변형 문구를 사용하도록 제한했다.
- 방 생성 단계의 밥·디저트 내기 선택을 제거하고 식사 내기로 고정했다.
- 디저트는 현재 옵션이 아니라 별도 메뉴 풀과 연출을 갖춘 향후 독립 모드로 분리했다.
- 여행자 모드와 국가·랜드마크 중심 배경 계획을 현재 범위에서 제거했다.
- 음식 가독성과 파티 분위기를 우선해 팝 아케이드 다이닝 테이블을 MVP 배경으로 확정했다.

## 제외한 내용 및 이유

- 최종 메뉴 자동 선택: 참가자 합의를 존중하기 위해 제외
- 가격대·매운맛·제외 음식 설정: 시작 피로도를 줄이기 위해 제외
- 참가자 준비 버튼: 대면 모임의 빠른 시작을 위해 제외
- 내기 종류 선택: 고정 규칙으로 시작 단계를 단순화하기 위해 제외
- 현재 디저트 모드: 식사 MVP의 완성도를 우선하고 향후 독립 모드로 분리
- 여행자 모드·랜드마크 배경: 핵심 식사 내기 경험과 직접 관련이 없어 현재 로드맵에서 제외
- 메뉴별 이미지 변형: 50개 기본 콘텐츠의 품질을 우선하기 위해 제출 이후로 연기
- 인앱결제: 핵심 플레이와 무관하므로 해커톤 MVP에서 제외
