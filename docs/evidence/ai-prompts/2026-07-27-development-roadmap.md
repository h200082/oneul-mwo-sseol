# 개발 및 제출 로드맵 작성

- 날짜: 2026-07-27
- 도구·모델: Codex
- 작업 목적: 확정된 게임 기획을 실제 개발·배포·제출 단계로 분해
- 관련 파일: `docs/source/development-roadmap.md`

## 사용자 요청

최종 기획 이후 앞으로 진행해야 할 단계를 정리해 달라는 요청을 받았다.

## AI가 검토한 영역

- 핵심 조작과 점수 계산의 기술 위험
- 1인 플레이와 2~8인 방의 구현 의존성
- 음식 50개, 배경, 연출, 음향의 제작 순서
- Firebase 방 상태와 예외 처리
- 모바일·데스크톱 QA
- GitHub Pages, YouTube, PDF 제출물의 동결 순서

## 주요 제안

- 베기·포획과 면적 점수를 가장 먼저 시제품으로 검증
- 음식 그림과 점수 판정을 분리하고 동일한 표준 스티커 마스크 사용
- 실제 휴대폰 2대의 QR 방 참가를 개발 초기에 검증
- 대표 음식 5개 승인 후 나머지 45개 양산
- P0·P1·P2로 범위를 나누고 P0 통과 전 확장 기능 금지
- 개발과 동시에 AI 프롬프트·에셋 출처·라이선스 기록
- 최종 배포 버전으로 플레이 영상과 PDF 제작

## 사람이 확정하거나 추가로 입력해야 하는 항목

- 실제 제출 마감일
- 개인 또는 팀 참여 여부
- Git 작성자 이름과 이메일
- GitHub 저장소 소유 계정
- Firebase 프로젝트 소유 계정
- 실제 테스트에 사용할 Android·iPhone 기기

## 반영 결과

- 현재 상태와 첫 블로커 기록
- M0부터 M9까지의 단계별 산출물과 완료 조건
- 개발·콘텐츠·문서 병렬 작업 구조
- 출시 차단 오류와 위험 대응
- 마감일 기준 역산 동결 일정
- 바로 시작할 첫 작업 목록

## 범위 판단

핵심 조작, 1인 루프, 최대 8인 방, 결과 화면과 제출 안정성을 P0로 유지했다. AI 음성, 업적, 추가 도구와 결과 공유는 핵심 안정화 이후로 미뤘으며 디저트 모드는 제출 이후 독립 모드로 유지했다.
