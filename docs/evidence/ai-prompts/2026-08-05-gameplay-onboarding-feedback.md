# 게임 온보딩·판정 피드백 개선

- 날짜: 2026-08-05
- 도구·모델: OpenAI Codex (GPT-5 기반)
- 작업 목적: 멀티플레이 안정화 이후 새 음식 이미지를 만들기 전에, 처음 접하는 사용자가 베기·포획과 점수 상태를 빠르게 이해하도록 첫 플레이 안내와 인게임 피드백을 보강
- 관련 파일·기능: `src/app/AppController.ts`, `src/app/app.css`, `src/game/gameFeedback.ts`, `src/game/scenes/PrototypeScene.ts`, `tests/gameFeedback.test.ts`, `tests/e2e/smoke.spec.ts`, `docs/source/game-guide.md`

## 주요 프롬프트·지시 사항

사용자는 현재 아이폰으로 재검증할 수 없지만 성공한 게임 흐름은 정상적으로 운영되고 있다고 설명하고, 모바일 방 안정화의 실기기 확인을 기다리는 동안 게임 디테일 개선을 먼저 진행하도록 요청했다.

이번 작업에서는 다음 조건을 지켰다.

- 새 음식 이미지는 생성하거나 교체하지 않는다.
- Firebase 문서 구조, 방 동기화, 결과 제출 규칙을 변경하지 않는다.
- 포획 최대 2회, 비포획 평균, 놓침 0점 등 확정된 게임 규칙을 유지한다.
- 처음 보는 사용자가 별도의 긴 설명 없이 베기와 길게 누르기를 구분할 수 있게 한다.
- 방 플레이에는 참가자 준비 버튼이나 개인별 연습 대기를 추가하지 않는다.
- 판정 문구와 연출은 점수 공식을 바꾸지 않는 표현 계층으로 분리한다.
- 실제 단말 검증을 수행하지 않은 상태에서 Android 또는 iPhone 테스트를 완료했다고 기록하지 않는다.

대표 지시 요약:

> “아이폰 실기기 테스트는 나중에 이어가고, 현재 잘 운영되는 게임 규칙과 멀티플레이를 보존한 채 처음 플레이하는 사람이 조작과 피드백을 더 쉽게 이해하도록 디테일부터 개선한다.”

## 설계 결정

### 홈과 게임 시작 안내

- 홈에는 기본적으로 접혀 있는 `게임 방법` 영역을 추가해 필요한 사람만 규칙을 펼쳐볼 수 있게 했다.
- 혼자 하기의 새 게임은 첫 라운드 전에 베기, 포획, 놓침과 평균 규칙을 한 화면으로 설명한다.
- 솔로 시작 안내는 약 2.3초 후 자동으로 닫히고, 화면을 누르면 기다리지 않고 바로 시작한다.
- 방 플레이는 개인별 안내 화면으로 시작을 막지 않는다. 공통 3초 카운트다운 안에 베기와 포획 조작 요약을 표시한다.

### 문맥형 초반 안내

- 첫 번째 음식에는 드래그 베기, 두 번째에는 0.3초 길게 누르기, 세 번째에는 포획이 선택이라는 안내를 각각 표시한다.
- 네 번째 음식부터는 음식 이름과 베기·포획을 한 줄로 함께 안내한다.
- 이 안내는 연습용 별도 라운드가 아니며 실제 20개 덱, 진행도와 점수 규칙을 그대로 사용한다.

### 절단 판정 피드백

- 정확도를 표시하는 표현을 네 단계로 나눴다.
  - 95 이상: `칼각!`
  - 80 이상 95 미만: `훌륭해요!`
  - 60 이상 80 미만: `좋아요!`
  - 60 미만: `아쉬워요`
- 등급, 한글 문구, CSS 색상과 Phaser 숫자 색상을 `src/game/gameFeedback.ts`의 순수 함수로 분리했다.
- 함수는 0~100 범위의 유한 숫자만 받으며 등급 판정에는 표시용 반올림 전 정확도를 사용한다.
- 등급은 팝업의 문구·색상·크기에만 영향을 주고 정확도나 평균 계산을 변경하지 않는다.

### 놓침·후반부·평균 상태

- 음식이 기준선까지 128px 이내로 접근하면 코럴색 경고선과 `놓치기 직전` 안내를 표시한다.
- 실제 놓침에는 `MISS · 0점` 팝업, 짧은 플래시와 흔들림을 사용해 평균에 0점이 들어갔음을 분명히 한다.
- 16번째 음식 직전에는 약 0.76초의 `FINAL 5` 배너를 보여주고 마지막 다섯 개 구간을 알린다.
- 아직 비포획 음식이 하나도 처리되지 않았으면 숫자 0 대신 `현재 평균 —`를 표시한다. 포획만 한 초기 상태를 평균 0점으로 오해하지 않게 하기 위한 결정이다.

## AI 지원 내용

- 현재 기획 문서와 구현을 대조해 새 이미지 없이 체감 효과가 큰 P0 디테일을 선별했다.
- 온보딩을 솔로 시작 안내, 방 카운트다운 요약, 초반 세 라운드 문맥 안내로 나누는 흐름을 제안했다.
- 네 단계 판정의 경계, 문구와 기존 UI 팔레트 색상을 순수 데이터로 구성했다.
- 잘못된 정확도 입력을 거부하는 검증과 경계값 단위 테스트를 작성했다.
- 놓침 경고, `MISS`, `FINAL 5`, 초기 평균 빈 상태의 문구와 연출 구현을 보조했다.
- 게임 소개 문서와 AI 활용 증빙 초안을 실제 반영 범위에 맞춰 갱신했다.

## 사람의 설계 제약과 검토

- 사용자가 원한 가벼운 플레이 흐름을 유지하기 위해 홈 설명은 항상 펼쳐 두지 않고 접힌 상태로 배치했다.
- 솔로 안내에는 탭 건너뛰기를 제공해 반복 플레이의 시작 피로를 줄였다.
- 방에서는 각자 안내를 닫을 때까지 기다리는 절차를 넣지 않아 방장의 즉시 시작과 공통 시각을 보존했다.
- 점수 등급은 경쟁 규칙이 아니라 이해를 돕는 연출로 제한했다.
- 콤보 보너스, 점수 배수, 포획 보너스처럼 기존 순위를 바꾸는 기능은 추가하지 않았다.
- 음식 이미지와 오디오 에셋은 이번 작업 범위에서 생성·수정하지 않았다.

| 영역 | 반영 내용 |
|---|---|
| 홈 | 기본 접힘 상태의 게임 방법과 핵심 규칙 요약 |
| 솔로 시작 | 자동 종료와 탭 건너뛰기를 지원하는 사전 조작 안내 |
| 방 시작 | 공통 카운트다운 안의 베기·포획 요약 |
| 초반 플레이 | 첫 세 음식의 문맥형 조작 힌트 |
| 베기 결과 | 네 단계 평가 문구·색상과 정확도 팝업 |
| 놓침 | 기준선 접근 경고, `MISS · 0점`, 플래시·흔들림 |

| 테스트 | 판정 경계·유효성 단위 테스트와 홈 안내 E2E 보강 |

## 테스트와 확인 상태

자동 검증에 다음 항목을 반영했다.

- `tests/gameFeedback.test.ts`: `0`, `59.9`, `60`, `79.9`, `80`, `94.9`, `95`, `100`의 판정 경계, 소수 첫째 자리 반올림 경계, 음수, 100 초과, `NaN`, 양·음의 무한대 거부
- `tests/e2e/smoke.spec.ts`: 홈 안내 접힘·펼침, 솔로 안내 탭 건너뛰기의 무소비, 모바일 Chromium 프로필의 합성 터치 드래그 베기 검증
- 개발 디버그 상태: 솔로 시작 안내 표시 여부, 놓침 경고 활성 상태, `FINAL 5` 안내 여부를 브라우저 자동화에서 관찰할 수 있게 노출

최종 자동 검증 결과는 다음과 같다.

- `npm run typecheck`: 통과
- `npm test`: 209개 통과, 13개 조건부 제외
- `npm run build`: 통과
- `npx playwright test tests/e2e/smoke.spec.ts`: 18개 통과, 8개 조건부 제외
- `npm run test:e2e`: 37개 통과, 15개 조건부 제외

## 아직 완료하지 않은 확인

- 실제 Android Chrome과 iPhone Safari에서 시작 안내의 글자 크기, 2.3초 체류 시간과 탭 건너뛰기 체감 확인
- 실제 터치 플레이에서 놓침 경고가 제스처와 음식 식별을 가리지 않는지 확인
- 작은 모바일 화면과 노치 환경에서 `FINAL 5`, 판정 팝업과 HUD 겹침 확인
- 운영 GitHub Pages 배포 후 공개 URL에서 동일 흐름 재확인

이번 기록 시점에는 실제 Android·iPhone 단말 테스트나 GitHub Pages 재배포를 수행하지 않았다.

## 제외한 내용 및 이유

- 대화형 연습 전용 라운드: 별도 상태와 반복 시도 대신 짧은 시작 안내와 실제 초반 문맥 힌트로 범위를 제한
- 점수 공식·난이도·덱 변경: 기존 공정성과 멀티플레이 결과를 보존
- 새 음식 이미지: 사용자가 전체 형태 규격을 정한 뒤 일괄 교체하기로 했으므로 제외
- BGM·효과음·AI 음성: 이번 온보딩·시각 피드백 작업과 분리해 후속 단계로 유지
- 업적·도구 스킨·콤보·개인 최고 기록: P0 디테일과 실기기 안정성 검증 이후 검토
