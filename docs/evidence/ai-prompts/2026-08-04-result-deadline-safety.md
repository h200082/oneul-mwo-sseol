# 결과 마감·미완주 안전망

- 작업일: 2026-08-04
- 목적: 잠긴 참가자 한 명의 결과 누락으로 공동 결과가 무기한 대기하는 P0 실패 방지
- 사용 도구: Codex(위험 감사, 도메인·Firestore·UI 설계, 구현·테스트·문서화 보조)
- 이미지 생성: 이번 작업에서는 ImageGen을 호출하지 않았고 이미지 에셋을 생성·수정하지 않음

## 사용자의 핵심 지시

```text
8월 10일 제출 마감에 맞춰 다음 단계를 진행한다.
공개 배포 이후 남은 P0 차단 요소를 우선 해결한다.
```

## AI가 확인한 위험

기존 구현은 시작 때 잠근 명단의 모든 결과가 도착해야만 공동 결과를 공개했다. 한 참가자가 브라우저를 닫거나 네트워크에서 영구 이탈하면 나머지는 정상 완주해도 결과 화면으로 이동할 수 없었다. 첫 구현 검토에서는 마감 직후 캐시·부분 스냅샷을 최종 결과로 오인할 경쟁 조건과 Firestore schema v1→v2 비원자 배포 위험도 발견했다.

## 설계 판단

1. 최악의 정상 20라운드는 약 50초이므로 공통 `startAt`에서 180초 뒤를 논리적 `resultDeadlineAt`으로 고정했다.
2. 실시간 결과 스냅샷은 진행률만 갱신하며 누락자를 DNF로 만들 권한이 없다.
3. Firestore 서버가 `request.time`으로 180초 마감과 5초 동기화 유예를 확인한 sentinel 읽기만 최종화 권한으로 사용한다.
4. sentinel 확인 뒤 `getDocsFromServer()`로 다시 읽은 결과 집합에서만 누락자를 0점·빈 포획 DNF로 합성한다.
5. 본인 결과 제출이 진행 중이면 완료·거부가 확정될 때까지 기다린 뒤 sentinel과 서버 결과를 순서대로 읽는다.
6. 0점 정상 완주자는 DNF보다 항상 높은 순위이며 전원 DNF면 승자와 내기를 만들지 않는다.
7. Firestore 코덱과 Rules는 v1·v2를 함께 읽고 검증한다. 무중단 Phase A에서는 v1을 기록하고, 운영 Rules 선배포·공개 QA 뒤 v2 기록으로 전환한다.

## 구현 결과

| 영역 | 반영 내용 |
|---|---|
| 방 도메인 | 180초 결과 창, 5초 동기화 유예, 파생 `resultDeadlineAt` |
| 로컬 게이트웨이 | 마감 후 신규 제출 거부, 권위 상태 `open/closed`, 기존 v1 저장값 deadline 파생 |
| Firebase 코덱 | v1·v2 이중 읽기, v1 deadline 파생, v2 명시값 검증, Phase A v1 기록 |
| Firestore Rules | v1·v2 시작 구조 검증, 서버 시각 늦은 제출 차단, 읽기 전용 마감 sentinel |
| 결과 도메인 | 서버 확인 전 pending, 확인 후 DNF, 0점 완주 우선, 전원 DNF 내기 없음 |
| 앱 흐름 | 제출 task 정리 후 sentinel→서버 결과 조회, 재시도, 재접속 분기, DNF 카드, 타이머 정리 |

## 사람의 검토와 수정

- 1차 구현의 `Date.now() >= deadline` 확정을 제거해 빠른 기기 시계와 부분 스냅샷이 DNF를 만들지 못하게 했다.
- 마감 handler가 게임을 먼저 중단하지 않고 서버 sentinel이 `closed`일 때만 게임을 종료하도록 순서를 바꿨다.
- 전원 DNF 화면에서 `공동 1위` 대신 단순 `미완주`로 표시해 의미 충돌을 제거했다.
- 카운트다운은 숫자 노드만 갱신해 버튼 이벤트와 포커스를 매초 재생성하지 않게 했다.
- v1 앱과 v2 앱·Rules 사이에 즉시 단절이 생기지 않도록 이중 읽기·이중 규칙과 단계적 기록 전환을 선택했다.

## 검증

- 전체 단위 테스트 187개 통과, 환경 의존 12개 제외
- Firestore Rules 에뮬레이터 통합 테스트 12개 통과
- 마감 E2E에서 두 페이지 시계를 함께 가속하고 양쪽 순위·DNF 결과가 동일함을 확인
- 정상 0점 완주가 DNF보다 위에 배치되고 전원 DNF는 내기 없음으로 처리됨을 확인
- 결과에서 홈으로 이동한 뒤 이전 마감 타이머가 화면을 다시 열지 않음을 확인

## 남은 실제 기기 검증

- Android Chrome과 iPhone Safari 두 기기에서 20라운드 완주
- 한 기기의 실제 네트워크 종료·복귀와 180초+5초 마감 관찰
- 기기 시계 차이가 예상 카운트다운 표시에 미치는 영향
- 운영 Rules 선배포 후 Phase A 공개 URL Firebase 방 생성·참가 smoke

App Check, 서버 판정·리플레이 검증, 라운드 진행 지점 복구는 이번 안전망 범위 밖의 후속 보안·공정성 작업이다.
