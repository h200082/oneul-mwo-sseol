# 게임 효과음·진동 피드백

- 날짜: 2026-08-05
- 도구·모델: OpenAI Codex (GPT-5 기반)
- 작업 목적: 이미지 교체 전 단계에서 베기·포획·놓침·후반부·결과의 손맛을 높이고, 여러 명이 같은 장소에서 플레이해도 과도하게 시끄럽지 않은 짧은 피드백 체계를 구현
- 관련 파일·기능: `src/feedback/`, `src/app/AppController.ts`, `src/app/GameHost.ts`, `src/app/app.css`, `src/game/createGame.ts`, `src/game/scenes/PrototypeScene.ts`, `tests/feedbackSettings.test.ts`, `tests/sensoryFeedback.test.ts`, `tests/browserSensoryFeedbackOutput.test.ts`, `tests/e2e/sensory-feedback.spec.ts`, `tests/e2e/room-flow.spec.ts`

## 사용자 요청

> 이제 사운드 진동 피드백 진행하자.

## AI에 준 주요 지시와 판단 기준

- 외부 음원·유료 라이선스 없이 GitHub Pages에서 바로 재생할 수 있게 한다.
- Web Audio 자동재생 제한 때문에 게임 시작을 막거나 오류를 노출하지 않는다.
- iPhone처럼 표준 진동 API를 지원하지 않는 환경을 정상 fallback으로 처리한다.
- 베기, 포획, 놓침, `FINAL 5`, 결과에 의미가 다른 짧은 피드백을 한 번씩만 연결한다.
- 여러 참가자의 휴대전화가 동시에 재생될 수 있으므로 BGM과 긴 음성은 이번 범위에서 제외하고 방 모드 볼륨을 낮춘다.
- 효과음과 진동 설정을 분리하고 브라우저에 저장한다.
- 시각 피드백은 그대로 유지해 소리와 진동이 정보 전달의 유일한 수단이 되지 않게 한다.

## AI가 제안·생성한 결과

### 앱 수명주기 공유 서비스

- `SensoryFeedbackController`가 설정, 의미 큐, 출력 횟수와 최근 큐를 관리한다.
- `BrowserSensoryFeedbackOutput`이 앱 수명주기 동안 하나의 `AudioContext`를 재사용한다.
- 마우스는 `pointerdown`, 터치·펜은 `pointerup`, 키보드는 `keydown`에서 브라우저 오디오 잠금 해제를 시도한다.
- 터치·펜 `pointerdown`에서는 권한을 요청하지 않고 최대 2.5초의 제스처 토큰만 만든다. 포획처럼 손을 떼기 전에 판정되면 최신 효과음·진동 한 건을 이 토큰에 보관한다.
- `pointerup`에서는 보류 진동을 한 번 방출하고 오디오 잠금 해제 성공 후 보류 효과음을 재생한다. `pointercancel`, 숨김, 게임 종료, 만료 시에는 둘 다 폐기해 다음 입력에 오래된 효과가 섞이지 않게 한다.
- 탭이 숨겨지면 진행 중인 oscillator와 진동을 정리하고, 늦게 끝난 `resume()`도 다시 suspend한다.
- 노드 생성·예약 중 오류가 나도 oscillator, gain, 미완성 컨텍스트를 정리하며 게임 진행에는 예외를 전파하지 않는다.
- 앱 자체가 종료될 때만 오디오 컨텍스트를 닫는다.

### 이벤트별 피드백

| 이벤트 | 효과음 방향 | 진동 패턴(ms) |
|---|---|---|
| 낮은·보통·좋은 베기 | 정확도에 따라 음높이가 오르는 70~150ms 칼날음 | `24` / `30` / `38` |
| `칼각!` | 짧은 고음 3단 sparkle | `34, 24, 48` |
| 포획 | 상승형 3단 차임 | `42, 30, 62` |
| 놓치기 직전 | 짧은 저음 경고 | 없음 |
| 놓침 확정 | 짧은 하강음 | `48` |
| `FINAL 5` | 2음 상승 신호 | `28, 30, 40` |
| 결과 | 350ms 이내 완료 차임 | `34, 36, 56` |
| 방 카운트다운 | 낮은 짧은 beep, 시작 시 상승 신호 | 시작 시 `26` |

각 효과는 Oscillator와 Gain envelope로 실행 중 생성한다. 사운드 파일을 저장소에 추가하지 않았고 제3자 음원을 샘플링하지 않았다.

### 설정과 접근성

- 홈에 `효과음 ON/OFF`, `진동 ON/OFF` 버튼을 각각 제공한다.
- 게임 HUD 우측 상단에서도 `♪`, `VIB` 버튼으로 빠르게 바꿀 수 있다.
- 설정 키 `oneul-mwo-sseol-feedback-v1`에 두 Boolean 값만 저장한다.
- 진동 미지원 환경에서는 진동 버튼을 비활성화하고 `진동 미지원`과 접근 가능한 설명을 표시한다.
- 홈 DOM 버튼은 최소 44px 터치 영역, `aria-pressed`, 동작을 설명하는 접근성 이름을 갖는다.

## 사람의 검토와 수정

- 같은 장소에서 최대 8대가 동시에 울리는 상황을 고려해 BGM과 AI 밈 음성을 이번 구현에서 제외했다.
- 포획과 `칼각!`만 보상 진동을 강조하고, 자주 발생할 수 있는 놓침은 한 번의 짧은 진동으로 줄였다.
- 놓치기 직전 경고는 화면 경고와 겹치므로 진동 없이 짧은 소리만 사용했다.
- 2026-08-07 노트북 방장→Android QR 참가 2인 실기기 확인에서 효과음·진동·베기 점수 단계는 정상 동작했지만 강도가 약하다는 검토를 반영했다.
- 마스터 출력을 72%에서 78%로, 방 플레이 효과음을 72%에서 86%로, 카운트다운을 70%에서 80%로 높였다. 방 플레이의 유효 출력은 약 29% 증가하지만 솔로보다 낮게 유지된다.
- 일반 베기 진동은 판정별 24/30/38ms로 강화하고, 칼각!과 포획은 구분되는 다중 펄스를 유지했다.
- 방 결과 효과는 Phaser 종료 정리 이후 공동 결과 화면이 확정된 시점에 한 번 재생해 전환 중 잘리지 않게 했다.
- 베기·포획 입력 중에는 놓치기 직전 경고음을 생략해 판정음과 겹치지 않게 했다.
- Pixel 7 브라우저 프로필 렌더링을 확인해 홈 설정 칩과 게임 HUD 버튼이 제목·점수 표시와 겹치지 않게 배치했다.
- iOS 비표준 햅틱 우회 기법은 사용하지 않았다.
