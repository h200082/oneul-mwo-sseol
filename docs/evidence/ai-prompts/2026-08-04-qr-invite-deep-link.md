# 모바일 QR 초대·자동 입장

- 작업일: 2026-08-04
- 목적: Android에서 만든 방의 QR을 iPhone 카메라로 열었을 때 일반 홈에 머무는 문제 해결
- 사용 도구: Codex(원인 분석, 초대 UX·저장 정책 설계, 구현·테스트 보조)
- 이미지 생성: 이번 작업에서는 ImageGen을 호출하지 않았고 이미지 에셋을 생성·수정하지 않음

## 사용자의 핵심 지시

```text
안드로이드로 방 생성해서 큐알코드를 아이폰으로 인식해 초대하면
방으로 초대되지 않고 홈페이지 화면으로 들어가져서 같은 방에 바로 들어와 지질 않아.
```

## AI가 확인한 원인

QR과 GitHub Pages 하위 경로는 정상이며 링크에는 `?room=방코드`가 포함되어 있었다. 문제는 앱이 이 값을 읽은 뒤 방 코드 입력란에만 채우고 실제 참가 함수는 호출하지 않는 흐름이었다. 닉네임도 `sessionStorage`에만 저장되어 iPhone 카메라가 새 Safari 탭을 열면 이전 닉네임을 재사용하기 어려웠다.

## 설계 판단

1. 유효한 초대 링크에서는 혼자 하기·방 만들기·식사 시간·앱 내부 QR 스캔을 숨기고 초대 전용 화면을 표시한다.
2. 첫 방문자는 결과 화면에서 식별할 수 있도록 임의 게스트 이름을 만들지 않고 닉네임을 한 번 입력한다.
3. 첫 입력 뒤 Firebase 환경에서는 닉네임을 `localStorage`와 `sessionStorage`에 저장해 이후 QR부터 자동 참가한다.
4. 로컬 다중 탭 백엔드는 참가자 이름이 다른 탭과 섞이지 않도록 기존 `sessionStorage` 격리를 유지한다.
5. 저장소 접근은 Safari 개인정보 보호 설정에서 실패할 수 있으므로 모든 읽기·쓰기를 예외 안전하게 처리한다.
6. 자동 참가 실패 시 초대 화면과 `room` 쿼리를 유지해 같은 화면에서 재시도할 수 있게 한다.
7. 사용자가 ‘다른 방 찾기’를 명시적으로 눌렀을 때만 URL에서 `room`을 제거한다.

## 구현 결과

| 영역 | 반영 내용 |
|---|---|
| 초대 진입 | `?room=` 감지 시 전용 화면, 읽기 전용 방 코드, ‘이 방에 참가’ 버튼 |
| 첫 참가 | 닉네임 입력 후 버튼 또는 Enter로 참가 |
| 재방문 | Firebase 저장 닉네임이 있으면 링크 로드 직후 같은 방 자동 참가 |
| 복귀 | 대기실·게임 중·결과 대기 중 새로고침도 수동 참가 버튼 없이 복귀 |
| 취소 | ‘다른 방 찾기’로 쿼리 제거 후 일반 홈 복원 |
| 모바일 UI | 작은 화면에서도 참가 버튼이 뷰포트 안에 보이는 초대 카드 레이아웃 |

## 사람의 검토와 수정

- 첫 QR부터 무조건 입장시키는 임의 `게스트 XXXX` 정책은 등수·포획 메뉴에서 참가자를 구분하기 어렵다고 판단해 제외했다.
- 공유 기기의 오래된 닉네임이 자동 사용될 수 있다는 트레이드오프를 확인했다. MVP는 빠른 대면 참가를 우선하고, 추후 대기실 닉네임 변경 기능을 검토한다.
- QR 생성기나 GitHub Pages base 경로는 정상이라 변경하지 않고 진입 후 앱 흐름만 수정했다.
- 프로덕션 Firebase와 로컬 E2E의 저장소 범위를 분리해 같은 브라우저 여러 탭 참가 테스트가 호스트 닉네임을 공유하지 않게 했다.

## 검증

- 프로덕션 빌드 성공
- 전체 단위 테스트 192개 통과, 환경 의존 12개 제외
- 데스크톱 방 흐름 E2E 8개 통과
- 저장 닉네임만 준비한 참가자가 클릭 없이 같은 방의 2/8 대기실로 이동함을 확인
- 첫 초대 화면의 읽기 전용 코드, 숨겨진 일반 홈 액션, Enter 참가, 초대 취소를 확인
- Pixel 7 모바일 Chromium에서 초대 화면과 참가 버튼이 뷰포트 안에 표시됨을 확인

## 남은 실제 기기 검증

- 배포 후 Android Chrome 방 생성 → iPhone Safari 카메라 QR 최초 참가
- iPhone에서 닉네임 입력 후 새 QR을 다시 열었을 때 자동 참가
- Safari 비공개 모드에서 저장 없이도 수동 참가 가능한지 확인
