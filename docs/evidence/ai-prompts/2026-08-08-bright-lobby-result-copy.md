# 크림 스카이 로비·결과 화면과 결과 문구 정리

- 날짜: 2026-08-08
- 도구·모델: OpenAI Codex
- 작업 목적: 홈에서 확정한 밝은 크림 스카이 시각 언어를 멀티플레이 흐름에 연결하고, 결과 추천 문구와 겹침 횟수를 더 직관적으로 표현
- 관련 파일: `src/app/AppController.ts`, `src/app/app.css`, `tests/e2e/room-flow.spec.ts`

## 사용자 요구

- 생성된 방의 대기실과 게임 결과 화면도 밝은 배경으로 통일한다.
- 결과 화면의 `단독 1등 메뉴`를 방의 식사 시간에 맞는 `1등의 점심 PICK` 또는 `1등의 저녁 PICK`으로 바꾼다.
- `공동 최다 겹침 메뉴`를 `가장 많이 겹친 메뉴`로 바꾸고 실제 선택 횟수를 함께 표시한다.
- 이미 확정된 게임 플레이와 QR 동작은 훼손하지 않는다.

## 시각 범위와 구현 판단

Cream Sky 팔레트를 다음 세 화면에 확장했다.

- `lobby-screen`: 방 코드, 초대 QR, 참가자 명단과 시작 버튼이 있는 생성 방 화면
- `results-waiting-screen`: 각 참가자의 결과 제출을 기다리는 화면
- `room-results-screen`: 순위, 1등의 PICK, 가장 많이 겹친 메뉴와 내기 결과를 보여주는 최종 화면

세 화면의 바깥 배경은 따뜻한 크림·피치 그라데이션으로, 주요 패널은 밝은 아이보리와 옅은 민트로 정리했다. 글자는 짙은 남색, 핵심 동작은 코랄, 상태 정보는 청록을 사용해 홈과 같은 계층을 유지했다.

적용 범위를 멀티플레이 UI 컨테이너로 제한해 실제 게임 캔버스, 게임 시작 카운트다운, 카메라 QR 스캐너 화면은 기존의 어두운 아케이드 배경과 동작을 유지했다. 밝은 스타일 때문에 플레이 중 대비나 카메라 인식성이 달라지지 않도록 한 판단이다.

## 결과 문구와 데이터 사용

- 최종 결과 렌더러가 이미 전달받는 `StartedRoom.mealTime`을 사용해 `lunch`는 `점심`, `dinner`는 `저녁`으로 표시한다.
- 완주자가 한 명 이상이면 단독 우승은 `1등의 {점심|저녁} PICK`, 공동 우승은 `공동 1등의 {점심|저녁} PICK`으로 표시한다. 완주자가 없을 때는 `완주자 없음`을 유지한다.
- 겹침 섹션 제목을 `가장 많이 겹친 메뉴`로 바꿨다.
- 기존 `MostOverlappedMenu.captureCount`를 사용해 제목 우측과 각 메뉴 카드에 `N회 선택`을 표시한다. 겹친 메뉴가 없으면 제목 우측에 `0회 선택`을 표시한다.
- `captureCount`는 동일 메뉴를 선택한 참가자 수를 기존 결과 집계가 계산한 값이다. 여러 메뉴가 공동 최다이면 같은 최대 횟수를 가진 모든 메뉴를 그대로 보여준다.

화면에 이미 존재하는 `mealTime`과 `captureCount`만 활용했으므로 Firestore 문서 구조·보안 규칙·인덱스와 도메인 타입·집계 규칙은 변경하지 않았다.

## 사람의 검토와 보정

- 밝은 배경에서도 방 코드, 참가 인원, 결과 대기 상태와 최종 순위가 먼저 읽히도록 카드 대비를 조정했다.
- 음식 이미지 주변의 밝은 슬롯과 빈칸 슬롯이 혼동되지 않는지 확인했다.
- 우측 횟수 배지가 긴 제목과 충돌하지 않도록 모바일 너비에서 줄바꿈과 여백을 확인했다.
- 실제 게임, 카운트다운, QR 스캐너가 밝은 테마 선택자의 영향을 받지 않는지 범위를 검토했다.
