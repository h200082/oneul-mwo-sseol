# 회전 음식 단계 난이도와 최종 좌우 이동

- 날짜: 2026-08-08
- 도구·모델: OpenAI Codex (GPT-5 기반)
- 작업 목적: 초반 학습과 멀티플레이 공정성을 유지하면서 단계적 회전과 마지막 두 음식의 좌우 왕복 난이도를 추가
- 관련 파일: `src/game/roundMotion.ts`, `src/domain/rigidTransform.ts`, `src/game/scenes/PrototypeScene.ts`, `tests/roundMotion.test.ts`, `tests/horizontalMotion.test.ts`, `tests/rigidTransform.test.ts`, `tests/e2e/rotation.spec.ts`, `tests/e2e/horizontal-motion.spec.ts`

## 사용자 요구

- 1~5번째 음식은 회전시키지 않는다.
- 이후 다섯 음식 단위로 회전량을 높인다.
- 같은 방의 같은 seed·라운드는 같은 회전 방향을 사용한다.
- 음식 그림과 알파 그림자만 회전하고 이름표는 정방향을 유지한다.
- 화면에서 회전한 알파 실루엣 그대로 베기 점수를 계산한다.
- 회전 때문에 포획이 지나치게 어려워지지 않게 기존의 관대한 조작 범위를 유지한다.
- 마지막 두 음식은 현재 속도와 회전을 유지하면서 좌우로 부드럽게 왕복한다.
- 음식 크기·오프셋·알파 그림자를 고려해 화면 밖으로 나가지 않게 이동 폭을 제한한다.

대표 지시 요약:

> “초반에는 조작을 익히게 두고 6번째부터 음식 그림이 단계적으로 회전하게 한다. 라벨은 똑바로 고정하고, 회전한 모양 그대로 베기 점수와 포획에 반영하며 같은 seed는 같은 움직임을 재현한다. 마지막 두 음식은 좌우로 이동해 클라이맥스를 만든다.”

## 설계 결정

### 라운드별 회전 단계

| 음식 순서 | 회전량 | 목표 각도 절댓값 | 의도 |
|---|---:|---:|---|
| 1~5 | 0회전 | 0도 | 조작 학습과 형태 인지 |
| 6~10 | 0.5회전 | 180도 | 회전 도입 |
| 11~15 | 0.75회전 | 270도 | 방향 변화 대응 |
| 16~20 | 1회전 | 360도 | 마지막 다섯 음식의 최고 난이도 |

회전 tween은 각 음식의 낙하 시간 전체에 `Linear`로 진행된다. 기존 낙하 속도는 변경하지 않았다.

### seed 기반 회전 방향

시계·반시계 방향은 외부 난수나 덱 RNG를 소비하지 않고 정규화한 `deckSeed`와 라운드 인덱스만 해시해 결정한다. 같은 seed·라운드는 모든 기기에서 같은 방향을 재현하고 메뉴 20종 추첨 결과에도 영향을 주지 않는다.

### 최종 두 음식 좌우 왕복

| 음식 순서 | 요청 진폭 | 왕복 주기 | 시작 위치 |
|---|---:|---:|---:|
| 19번째 | ±32px | 1회 | 화면 중앙 |
| 20번째 | ±46px | 1.5회 | 화면 중앙 |

낙하 tween의 진행률에 `sin(2π × 주기 × 진행률)`을 적용해 별도의 X tween 없이 부드럽게 왕복한다. 최초 방향은 회전과 별도의 salt를 사용하는 `deckSeed + roundIndex` 해시로 결정하므로 같은 방에서 동일하다. 음식·그림자·이름표를 담은 바깥 컨테이너가 함께 이동하며 낙하·회전 속도는 바꾸지 않는다.

화면 경계 제한은 음식 이미지, `gameplayOffset`, 두 알파 그림자의 중심과 크기, 이름표를 포함한 최대 회전 안전 반경으로 계산한다. 마지막 두 음식은 화면 중앙에서 시작하며 좌우 18px 안전 여백 안에 머문다.

### 회전 그림과 고정 라벨

음식 이미지와 알파 기반 그림자는 내부 `rotatingArtwork` 컨테이너에 넣고 회전 tween을 이 컨테이너에만 적용했다. 음식명과 라벨 판은 바깥 토큰 컨테이너에 남겨 항상 0도를 유지한다. 절단 후 두 조각에도 현재 각도를 넘겨 회전 상태가 초기화되지 않게 했다.

### 알파 실루엣 역변환

포인터 경로를 손을 놓은 순간의 음식 각도로 회전 전 로컬 좌표에 역변환한 뒤 기존 알파 실루엣 분할기에 전달한다. 계산된 절단선은 다시 같은 각도와 토큰 이동을 적용해 화면 연출에 사용한다. 따라서 비원형 음식의 보이는 방향과 면적 점수가 일치한다.

### 포획 난이도 완화

포획 중심과 진행 링은 현재 회전을 따라가지만 기존의 관대한 규칙은 유지한다.

- 포획 시작 반경: 80px
- 길게 누르기: 320ms
- 베기로 전환되는 이동: 14px 초과

## AI 지원 및 사람의 검토

AI는 단계별 회전 순수 함수, 덱 RNG와 독립적인 방향 해시, Phaser 중첩 컨테이너, 정·역 강체 변환, 최종 두 음식의 사인 왕복과 안전 반경 테스트 구성을 지원했다. 사람은 초반 5개 무회전, 라벨 정방향, 알파 마스크 기반 점수, 기존 포획 관대함, 19·20번째의 ±32px·±46px 이동을 확정했다. 방향 급전환, 무작위 속도, 1회 초과 회전과 회전 보너스 점수는 가벼운 흐름과 공정성을 해쳐 제외했다.

## 테스트와 확인

- `tests/roundMotion.test.ts`: 네 단계 경계, 동일 seed 재현, 양방향, 덱 RNG 비소비, 잘못된 입력 거부
- `tests/rigidTransform.test.ts`: 45·90도 정역변환과 알파 베기 점수 보존

- `tests/e2e/rotation.spec.ts`: 1~5 무회전, 6번째 0.5회전, 실제 tween 진행, 중첩 artwork와 라벨 0도, 같은 seed 재현
- `tests/e2e/horizontal-motion.spec.ts`: 데스크톱·모바일 실제 X 이동, 음식·그림자·라벨 동행, 안전 반경과 seed 방향 검증
- 기존 데스크톱·모바일 smoke E2E: 베기·포획·투명 영역 판정 회귀 확인

## 제외한 내용 및 이유

- 방향 급전환·가감속·1회 초과 회전: 예측성과 가벼운 흐름을 해쳐 제외
- 좌우 무작위 점프와 화면 가장자리까지의 이동: 조작의 억울함과 시각적 잘림을 막기 위해 제외
- 1~5번째 회전: 조작 학습 보존
- 라벨 회전: 가독성 저하
- 회전 보너스 점수: 기존 순위 규칙 변경 방지
- 포획 반경 축소: 회전과 포획 난이도의 중첩 방지
- Firestore 변경: seed와 라운드만으로 재현되어 불필요
