# 길게 누르기 포획·완화 베기 입력 개선

- 작업일: 2026-08-03
- 목적: 드래그 중 음식이 멈추는 문제와 엄격한 베기·원 그리기 포획의 입력 충돌을 해결
- 사용 도구: Codex(원인 분석, 상호작용 설계, 코드·테스트·문서 작성 보조)
- 이미지 생성: 이번 작업에서는 ImageGen을 호출하지 않았고 이미지 에셋을 생성·수정하지 않음

## 사용자의 핵심 지시

```text
드래그 도중 음식이 멈추는 현상을 해결한다.
베기는 반드시 테두리에서 테두리까지 지나야 하는 조건을 더 유하게 한다.
원을 그리는 포획은 베기와 겹치고 어려우므로 더블클릭이나 꾹 누르기를 검토한다.
```

## 설계 판단

1. 더블클릭은 낙하 중인 음식을 두 번 맞혀야 하므로 한 번 눌러 대상을 잠그는 길게 누르기보다 실패 가능성이 높다.
2. 포획은 약 0.32초 길게 누르기로 바꾸고, 최초 접촉점에서 14px을 넘겨 움직이면 같은 입력을 즉시 베기로 전환한다.
3. 드래그와 포획 대기 중 음식은 계속 낙하한다. 입력 때문에 낙하 시간을 정지시키지 않는다.
4. 이동 중인 음식과 실제로 접촉했는지는 매 샘플의 토큰 로컬 경로로 확인한다.
5. 분리 방향은 토큰 이동량에 의해 기울지 않도록 화면에서 사용자가 그은 경로의 방향을 사용한다.
6. 엄격한 테두리 교차를 우선하되, 음식 양쪽을 거의 덮은 경로는 양 끝을 각각 최대 32px만 보정해 안쪽 시작·종료도 인정한다.
7. 짧은 탭, 중심에서 먼 경로, 접선에 가까운 스침, 원형 루프, `touchcancel`은 행동과 라운드를 소비하지 않는다.

## 사람의 검토와 수정

- 포획 중 음식을 잠시 멈추는 안도 검토했지만 리듬 중단과 시간 악용 가능성이 있어 채택하지 않았다.
- 단일 포인터다운 원점만 사용하는 단순 보정은 느린 드래그가 이동 중인 음식과 실제로 만났는지 확인하기 어려워 제외했다.
- 최종안은 실제 접촉 경로와 시각적 의도 방향을 분리해 낙하 유지와 자연스러운 절단 각도를 함께 만족시켰다.
- 길게 누르기 완료 시 동일 포인터·동일 토큰·남은 포획권을 다시 확인해 음식 미스와의 경쟁 상태를 막았다.
- 기존 원형 포획 경로는 더 이상 포획이나 베기로 처리하지 않고 길게 누르기 안내를 표시하도록 정리했다.

## 검증

- 기하·제스처 집중 단위 테스트 63개 통과. 전체 `npm test`는 176개 통과, 8개 환경 의존 테스트 제외
- 한쪽 가장자리에서 바깥으로만 그은 경로와 같은 쪽 안쪽 경로가 점수로 처리되지 않는 반례 통과
- 음식 안쪽에서 시작·종료한 수평 드래그가 이동 중에도 `extended` 베기로 처리되고 화면 방향 0도를 유지하는 데스크톱 E2E 통과
- 짧은 탭, 길게 누르기→베기 전환, 이동 중 포획, 성공 뒤 늦은 포인터 해제 E2E 통과
- 실제 모바일 길게 누르기와 `touchcancel` E2E 통과. 전체 E2E는 20개 통과, 프로젝트별 비대상 12개 제외
- 390×844 화면에서 포획 게이지·에너지 끈·베기 전환 문구가 겹치거나 잘리지 않는지 프레임 확인

## 포획 이동 정지 착시 후속 수정

- 실제 브라우저에서 마우스 홀드 중 음식 Y 좌표를 약 60ms 간격으로 계측한 결과, 포획 확정 전에는 `241.8 → 256.7 → 271.4 → 286.3 → 297.4 → 312.3`으로 계속 낙하했다.
- 포획 확정 뒤 기존 `Back.In` 이징이 음식을 `318.9 → 328.4 → 334.5`로 아래쪽에 되감은 뒤 위로 전환해, 공중에서 멈추는 것처럼 보이는 정지점을 만들었다.
- 포획 이동을 `Cubic.Out`으로 교체해 확정 직후부터 HUD 포획 슬롯 방향으로 빠르게 이동하고 끝에서만 자연스럽게 감속하도록 수정했다.
- E2E는 포획 임계시간 직전 260ms까지 낙하가 계속되는지와 포획 직후 세 Y 표본이 연속으로 감소하는지를 검증한다.
- 전체 단위 테스트 176개와 전체 E2E 20개가 통과했고, 12개는 프로젝트별 비대상 조건으로 제외했다. 타입 검사와 프로덕션 빌드도 통과했다.

## 모바일 LAN 후속 수정

- 증상: 휴대전화가 `http://192.168.123.111:4173/`로 접속하면 홈은 보이지만 `혼자 하기`를 눌러도 게임이 시작되지 않았다.
- 원인: LAN의 일반 HTTP 주소는 비보안 컨텍스트이므로 `crypto.randomUUID()`가 제공되지 않았고, 덱 시드 생성에서 동기 예외가 발생했다. 로컬 백엔드의 플레이어 ID 생성에도 같은 잠재 오류가 있었다.
- 구현: 보안 컨텍스트에서는 기본 `crypto.randomUUID()`를 유지하고, 사용할 수 없을 때는 `crypto.getRandomValues()`로 RFC 4122 버전 4 UUID를 생성하는 공용 도우미를 추가해 두 호출 경로를 교체했다.
- 회귀 방지: 기본 API 우선 사용과 결정적 폴백 형식을 단위 테스트하고, `crypto.randomUUID`를 제거한 Pixel 7 E2E에서 `혼자 하기` 후 캔버스 생성과 페이지 오류 없음까지 검증했다.
- 실제 LAN 확인: `isSecureContext=false`, `typeof crypto.randomUUID='undefined'` 상태에서 캔버스 1개와 페이지 오류 0건을 확인했다.
- 보안 경계: 이 폴백은 LAN HTTP에서 게임 실행과 수동·링크 방 참가를 돕는다. 카메라 QR 스캔은 브라우저 정책상 계속 HTTPS 보안 컨텍스트가 필요하다.
