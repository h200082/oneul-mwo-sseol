# 절차형 아케이드 배경음

- 날짜: 2026-08-08
- 도구·모델: OpenAI Codex (GPT-5 기반)
- 작업 목적: 짧은 음식 베기 플레이에 어울리는 경쾌한 배경음을 외부 음원 없이 직접 구성하고, 후반 난이도 상승을 음악의 밀도 변화로 자연스럽게 전달
- 관련 파일·기능: `src/feedback/arcadeBgm.ts`, `src/feedback/SensoryFeedback.ts`, `src/game/scenes/PrototypeScene.ts` 및 배경음 단위·브라우저 테스트

> 후속 변경 기록: 2026-08-10 효과음과 나레이션의 명료도를 높이기 위해 현재 런타임 스코어를 120 BPM·64-step으로 재편곡하고, 최고 기본음을 392Hz로 제한했으며 효과음 순간 자동 덕킹을 추가했다. 아래 128 BPM 내용은 최초 제작 당시 기록으로 보존한다.

## AI에 준 주요 지시와 판단 기준

- 저작권과 배포 제약이 없는 이 프로젝트 전용 오리지널 스코어를 만든다.
- 외부 음원 파일, 샘플, 스트리밍 음원을 사용하지 않고 Web Audio 노드로 실행 중 직접 합성한다.
- 음식 아케이드의 밝고 경쾌한 분위기를 유지하되 효과음과 조작 판정을 가리지 않게 낮은 음량으로 둔다.
- 1~20번째 음식의 회전·좌우 이동 난이도 변화와 같은 구간에서 음악의 층과 밀도도 단계적으로 높인다.
- 모바일 브라우저 자동재생 제한, iOS의 사용자 제스처 잠금 해제와 백그라운드 복귀를 기존 효과음 수명주기 안에서 처리한다.
- 배경음 전용 설정을 추가해 화면을 복잡하게 만들지 않고 기존 `사운드` 토글을 함께 사용한다.

## AI가 제안·생성한 결과

### 오리지널 절차형 스코어

- 128 BPM, 16분음표 단위 64-step(4마디·약 7.5초) 루프로 구성한다.
- G 장조 펜타토닉을 중심으로 베이스와 짧은 플럭 음형을 조합해 음식이 빠르게 내려오는 아케이드 리듬을 만든다.
- 저장된 오디오 파일을 재생하지 않고 Oscillator와 Gain envelope로 각 음을 런타임에 합성한다.
- 게임 재현성에 영향을 주는 난수는 사용하지 않으며, 같은 step과 구간에는 같은 음 이벤트가 반환되는 순수 스코어 데이터를 둔다.

### 플레이 구간별 밀도 변화

| 음식 순서 | 음악 구간 | 역할 |
|---|---|---|
| 1~5 | `opening` | 베이스와 핵심 플럭으로 조작 학습을 방해하지 않는 가장 단순한 편성 |
| 6~15 | `rotation` | 음식 회전 시작과 함께 보조 리듬을 추가 |
| 16~18 | `final-five` | 후반 진입을 느낄 수 있도록 고음 악센트와 리듬 밀도를 강화 |
| 19~20 | `final-two` | 좌우 이동 구간에 짧은 추가 음형을 얹어 마지막 긴장감을 강조 |

템포 자체는 끝까지 128 BPM으로 고정한다. 조작 속도가 갑자기 빨라진 것처럼 느껴지지 않게 하고, 편성의 밀도만 높여 난이도 상승을 알린다.

### 효과음과 분리된 재생 수명주기

- 배경음 전용 gain bus와 예약된 source 집합을 효과음 source와 분리한다.
- 짧은 look-ahead scheduler가 다음 step을 미리 예약해 모바일에서도 루프가 끊기거나 박자가 크게 흔들리지 않게 한다.
- 같은 구간을 다시 요청하면 곡을 처음부터 재시작하지 않고 현재 루프를 유지하며, 구간이 바뀌면 다음 예약 음부터 새 편성을 사용한다.
- `사운드 OFF`, 결과 화면 진입, 홈 복귀와 게임 종료에서는 배경음 source와 scheduler를 정리한다.
- iOS에서 AudioContext가 잠겨 있으면 재생 요청만 기억하고 다음 신뢰할 수 있는 사용자 제스처에서 시작한다.
- 탭이 숨겨질 때는 재생을 멈추고 컨텍스트를 suspend하며, 다시 보이고 사용자 입력으로 잠금이 풀리면 현재 구간에서 재개할 수 있게 한다.

## 사람의 검토와 수정

- 여러 명이 같은 장소에서 각자의 휴대전화로 플레이하는 상황을 고려해 배경음을 효과음보다 낮게 두고, 음량과 음색의 최종값은 실제 기기 청취 후 조정하기로 했다.
- 음식 6번째부터 회전, 16번째부터 후반, 마지막 2개에서 좌우 이동이 시작되는 현재 게임 규칙과 음악 구간을 일치시켰다.
- 별도의 BGM 토글은 라이트한 게임의 설정 피로도를 높일 수 있어 추가하지 않고 기존 사운드 토글에 포함했다.
- 오디오 파일을 저장소에 추가하는 방식 대신 코드로 읽을 수 있는 음표·리듬 데이터와 Web Audio 합성을 선택해 출처와 재현 과정을 명확히 했다.

## 외부 에셋·오픈소스 사용 여부

- 제3자 음악, 샘플 팩, 효과음, MIDI 파일과 스트리밍 음원을 사용하지 않았다.
- 멜로디·베이스·리듬 배열은 이 프로젝트를 위해 새로 구성했으며 브라우저 표준 Web Audio API로 실행 중 직접 합성한다.
- 따라서 배경음 자체에 별도 외부 에셋 라이선스나 출처 URL은 없다.

## 검증 상태

- 스코어·컨트롤러·브라우저 출력 단위 테스트 55개가 통과했다. 전체 Vitest는 379개 통과, 13개 스킵으로 기존 기능 회귀가 없음을 확인했다.
- 스코어의 64-step 주기성, 구간별 이벤트 밀도, 모바일 가청 저음 범위, 주파수·gain 안전 범위, 중복 scheduler 방지와 정리 동작을 검증했다.
- 데스크톱·모바일 Playwright 2개에서 네 단계 전환, 사운드 OFF·ON 재개, 사용자 제스처 잠금 해제, 결과 진입 시 BGM 중단과 결과 효과음 유지를 확인했다.
- TypeScript 타입 검사와 프로덕션 빌드가 통과했다. 실제 기기에서의 음색·볼륨 청취와 최종 미세 조정은 다음 검수 단계로 남겼다.

## 이번 범위에서 제외한 항목

- 외부 샘플과 녹음 음원: 저작권·파일 용량·루프 편집 부담을 피하기 위해 제외
- 별도 BGM 음량 슬라이더와 토글: 첫 시안은 기존 사운드 설정을 공유하고 실제 청취 뒤 필요성을 판단
- AI 밈 음성: 문구·생성 도구·권리 근거와 한 판 재생 횟수를 별도 검토해야 하므로 제외
- 플레이 결과 전용 완곡: 현재 결과 효과음을 유지하고 게임 진행 루프에 집중
