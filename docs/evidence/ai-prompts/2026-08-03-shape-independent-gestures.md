# 형태 독립 제스처·피드백 프로토타입

- 작업일: 2026-08-03
- 목적: 최종 음식 이미지가 원형이 아니어도 동일한 조작 난이도와 점수를 유지하도록 이미지·판정·연출 구조를 분리
- 사용 도구: Codex(코드·테스트·문서 작성 보조)
- 이미지 생성: 이번 작업에서는 ImageGen을 호출하지 않았고 새 이미지 에셋을 생성·추가하지 않음

## 사용자의 핵심 지시

```text
이미지는 나중에 생성한다. 게임할 때 음식이 무조건 원형이 아니라 다양한 형태여야 하므로,
지금은 이를 수용하는 구조를 만들고 최종 이미지는 한 번에 생성해 교체한다.
```

이 지시에 따라 기존 대표 5종 이미지는 임시 검증 에셋으로만 유지하고, 나머지는 새 이미지 대신 코드로 만든 여러 실루엣 폴백을 사용했다.

## 설계 판단

1. 음식 이미지는 원형으로 잘라 표시하지 않고 원본 가로세로 비율을 유지한다.
2. 가로형·세로형·불규칙형 이미지가 들어와도 공정하도록 점수 판정은 모든 메뉴에 같은 반지름의 원형 마스크를 사용한다.
3. 포획은 경로가 중심만 포함하는 것으로 부족하며, 단순 폐곡선이 공통 판정 원 전체를 감싸야 성공한다.
4. 닫혔지만 포획 조건을 만족하지 못한 경로는 베기로 재분류하지 않고 실패·재시도로 처리한다.
5. 최종 50종은 조작과 표시 규격을 승인한 뒤 실루엣·구도 표에 따라 한 작업 묶음으로 생성·선별·후처리한다.

| 영역 | 결과 | 반영 위치 |

| 포획 기하 | 폐곡선 중심 포함뿐 아니라 모든 경계 선분과 중심 사이 여유 거리로 판정 원 전체 포함 확인 | `src/domain/geometry.ts` |
| 비율 보존 | 원본 크기를 최대 표시 영역에 `contain` 방식으로 맞추는 순수 함수 | `src/data/menuVisuals.ts` |
| 임시 표시 | 원형 스티커 배경을 제거하고 이미지가 없는 메뉴는 타원·둥근 사각형·유기적 다각형으로 표시 | `src/game/scenes/PrototypeScene.ts` |

## 사람의 검토와 수정

- 판정 원을 화면의 원형 배경처럼 보이게 하지 않고 입력·점수용 데이터로만 유지했다.
- 실제 음식 실루엣보다 공통 판정 원이 공정성과 설명 가능성에 적합하다고 판단했다.
- 첫 베기 연출은 마스크가 월드 좌표에 고정돼 조각 이동 중 숨겨진 원본이 다시 보일 수 있어 기각했다.
- 최종 연출은 마스크를 토큰 중심의 로컬 좌표로 만들고 조각과 같은 위치·회전을 적용했다.
- 모바일 취소가 Phaser의 일반 포인터 종료로 전달될 수 있어 `pointer.wasCanceled` 분기를 추가했다.
- 포획 E2E의 점 수를 36개에서 16개로 줄여 2초 입력 제한 안에서 CI 안정성을 높였다.

## 자동·시각 검증

- 기하·제스처·이미지 비율 단위 테스트: 완전 포획, 중심만 감싼 경로, 자기 교차, 포획 한도, 가로형·세로형·정사각형을 포함
- 데스크톱 E2E: 실제 수평 베기 각도, 두 마스크 정리, 포획 슬롯 채움 확인
- 모바일 E2E: CDP의 실제 `touchCancel`을 보내 라운드·행동·경로가 소비되지 않는지 확인
- 브라우저 프레임 확인: 원형 스티커 배경이 없는 음식, 실제 절단선 기준 두 조각, 정확도 팝업, 포획 슬롯을 육안 검토

## 이번 작업에서 제외한 항목
