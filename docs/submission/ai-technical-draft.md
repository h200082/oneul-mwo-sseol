# 뭐 먹을 거냥? - AI 활용 기술 문서 (사전 제출본)

## 1. 활용 개요

이 프로젝트는 AI를 런타임 게임 판정에 호출하지 않고, 개발·콘텐츠 제작·검증 단계의 협업 도구로 사용했다. 실행 빌드에는 외부 AI API 키와 Speech SDK가 없으며, AI로 만든 이미지와 합성 음성은 사람이 검수한 정적 자산으로만 포함된다.

## 2. 사용 도구

| 도구 | 활용 범위 | 최종 반영 방식 |
|---|---|---|
| OpenAI Codex | 기획 구조화, TypeScript 구현, 알고리즘·테스트, 디버깅, 문서·프롬프트 기록 | 사람이 변경 범위와 결과를 검토한 뒤 소스와 테스트에 반영 |
| Codex 내장 ImageGen | 음식 이미지 50종과 타이틀 고양이 셰프 제작 | 사람이 시안을 선별하고 로컬 후처리한 투명 WebP만 포함 |
| Microsoft Azure AI Speech | 음식 문구 50종의 한국어 나레이션 후보 생성 | 사람 청취·A/B·블라인드 평가 후 정적 MP3/WAV 50개만 런타임 연결 |
| Pillow 12.3.0 | 크로마키 제거, despill, 알파 외곽 크롭, 리사이즈, WebP 인코딩·검사 | 로컬 재현 가능한 후처리 스크립트로 실행 |

## 3. Codex를 활용한 개발

Codex에는 결과만 요청하지 않고 목표, 금지 조건, 검증 기준을 함께 제공했다. 생성된 코드는 단위 테스트, Playwright E2E, Firestore Emulator 규칙 테스트, 타입 검사와 프로덕션 빌드로 검증해 왔으며 제출 commit에서 전체 검증을 다시 실행한다. 대표 적용 영역은 다음과 같다.

- 순수 함수 중심의 베기 정확도와 순위 규칙
- 실제 음식 알파 실루엣 기반 hit·면적 점수화
- 드래그 베기와 0.32초 길게 누르기 포획을 분리한 포인터 상태 머신
- 모바일 LAN의 비보안 HTTP에서도 동작하는 UUID 폴백
- 2~8명 방 생성·참가·시작·결과 동기화와 Firestore 보안 규칙
- QR 초대, 재접속, 공동 결과, DNF 마감 처리
- 회귀 테스트, 문서, 자산·해시 provenance 자동 검증

## 4. 주요 프롬프트와 사람의 판단

### 게임 규칙

주요 지시: “게임 규칙은 프레임워크에서 분리한 순수 함수로 작성하고 경계값을 자동 테스트한다.”

사람의 판단: 포획한 음식은 평균에서 제외하고, 놓친 음식은 0점으로 처리했다. 결과 순위와 내기 문구도 별도 규칙으로 고정했다.

### 조작 개선

주요 지시: “드래그 도중 음식이 멈추지 않게 하고 베기와 포획 입력이 충돌하지 않도록 한다.”

사람의 판단: 더블클릭과 일시정지는 이동하는 음식과 게임 리듬에 맞지 않아 제외했다. 길게 누르기와 이동 임계값을 결합해 Playwright 모바일 터치 에뮬레이션으로 검증했으며, 실제 iOS·Android 다기기 검증은 제출 전 남은 QA다.

### 실제 실루엣 판정

주요 지시: “원형 가정이 아니라 다양한 음식 그림 그대로 판정하고 그 차이가 점수에 반영되게 한다.”

사람의 판단: 128×128 가중 알파 마스크로 실제 불투명 픽셀 hit와 양쪽 면적을 계산했다. 투명 여백을 베거나 짧은 내부 선을 무한히 연장해 높은 점수를 얻는 회귀를 테스트로 차단했다.

## 5. AI 음식 이미지 제작

1. 음식 식별성, 먹음직스러움, 비원형 외곽, 작은 화면 가독성을 기준으로 프롬프트 작성
2. 기존 승인 8종은 유지하고 42종을 신규 생성·교정
3. 녹색·자홍색 크로마키를 로컬에서 제거하고 despill·soft matte 적용
4. 알파 외곽 기준으로 크롭하고 원본 종횡비를 보존한 채 긴 변 512px로 정규화
5. 투명 WebP, 크기 예산, 카탈로그 50종 일치, 다양한 종횡비를 자동 검사
6. 실제 Phaser 장면에서 50종을 하나씩 첫 라운드로 고정해 표시 크기·알파 마스크·베기/포획 중심을 전수 검수

제3자의 음식 사진이나 일러스트는 사용하지 않았다.

## 6. AI 합성 나레이션 제작

- 서비스: Microsoft Azure AI Speech Standard S0, southeastasia
- 보존 음성: 53개(활성 50개 + historical 3개)
- 활성 모델 구성: MAI-Voice-2-Flash 계열 45개, MAI-Voice-2 5개
- 사용 음성: `ko-KR-Haena:MAI-Voice-2-Flash`, `ko-KR-Junho:MAI-Voice-2-Flash`, `ko-KR-Junho:MAI-Voice-2`

메뉴별 문구와 연기 프로필을 생성한 뒤, 재생 길이만으로 자동 승인하지 않고 사람이 직접 청취했다. 필요한 경우 같은 문구의 A/B 후보, Flash와 Full 모델 블라인드 비교, 말 사이 무음 trim, 앞 공백 trim을 사용했다. 원본·후보·최종 자산의 바이트 수, SHA-256, 프레임 수, 길이, 승인 원문을 provenance 스크립트와 문서에 남겼다. 음성 복제나 실제 인물·방송·캐릭터 성대모사는 사용하지 않았다.

## 7. 런타임 구조와 보안

- 게임 실행 중 생성형 AI나 Azure API를 호출하지 않는다.
- Azure 키, 엔드포인트, Speech SDK를 배포 번들에 포함하지 않는다.
- 현재 문구와 일치하는 정적 MP3/WAV 50개만 메뉴 ID에 연결한다.
- 해당 라운드의 20종 덱에 필요한 오디오만 선로딩한다.
- 로드·디코드 실패 시 자막만 표시하는 폴백을 유지한다.
- 나레이션 중 BGM을 낮추고 종료 후 원래 음량으로 복귀한다.

## 8. 검증

- TypeScript 타입 검사: 현재 연출 변경분의 필드 선언 정합화 후 제출 commit에서 최종 재실행
- 전체 단위 테스트 705개 통과, 13개 의도적 skip
- Vite 배포 산출물 생성 통과, `npm run build`는 타입 검사 정합화 후 최종 재실행
- 활성 나레이션 50개·물리 자산 53개·릴리스 payload 50개 검증
- 데스크톱 나레이션 E2E 통과
- 음식 이미지 50종의 카탈로그·투명 WebP·용량·덱 선로딩 검증
- Firestore Emulator에서 인증, 방 상태 전이, 마감, 늦은 제출 거부, 결과 불변성 검증

## 9. 외부 에셋과 오픈소스

게임 런타임에는 제3자 음식·배경 이미지, 녹음 음성, 사운드 샘플, 외부 폰트를 사용하지 않았다. 효과음과 128 BPM 배경음은 외부 저장 음원 없이 Web Audio로 실행 중 생성한다. 주요 오픈소스는 Phaser 4.2.1(MIT), Vite 8.1.5(MIT), TypeScript 7.0.2(Apache-2.0), Vitest 4.1.10(MIT), Playwright 1.62.0(Apache-2.0), Firebase JavaScript SDK 12.16.0(Apache-2.0), qrcode 1.5.4(MIT), Pillow 12.3.0(MIT-CMU)이다. 제출 PDF는 ReportLab(BSD)과 pypdf(BSD-3-Clause), Windows 기본 맑은 고딕으로 제작했으며 게임 빌드에는 포함하지 않았다.

상세 출처·라이선스·확인일과 음원 인벤토리는 `docs/evidence/asset-licenses.md`에 기록했다.
